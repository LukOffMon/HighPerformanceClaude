Use the `high-performance` skill and follow `references/vibecoding.md`. Idea: $ARGUMENTS

- Silently extract the spec (who, job, 3 core flows, data, platform, out of scope). Ask at most one question, and only if a wrong guess would waste the whole build; otherwise decide and tell me your choices at the end.
- Use the existing repo stack if there is one; otherwise the default stack table.
- Build in vertical slices: running skeleton → core flow 1 with real persistence → flows 2–3 → states → polish pass.
- Meet the polish bar: real content, empty/loading/error states, responsive (375px–1440px), accessible, no framework boilerplate left behind.
- Verify like a user: production build passes, click through the flows, screenshot desktop and mobile and look at them, check the console.
- Finish with the hand-off message: how to run it, what's in it, how it was verified, choices made, next three improvements.
